Order evidence concept

Customer request → AI recommendation → customer approval → server validation → kitchen/QC → dispatch → delivery → integrity hash

This demo records the evidence architecture concept. It does not make legal conclusions and should not be treated as a production legal/audit system until backed by authenticated persistent storage, access controls and retention policies.

Production notes

  • MRR/Recall/Precision are calculated against the checked-in evaluation set, not invented dashboard values.
  • Groundedness is currently an evidence-overlap proxy. A production release should add an LLM judge with calibrated thresholds and human review.
  • RAG remains local token retrieval in V12; move to embeddings/vector search as the knowledge base grows.
  • Orders remain in-memory in this demo; production should use persistent authenticated storage and ownership controls.
